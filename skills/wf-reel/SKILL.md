# Recorded reel workflow

Read `../../docs/WORKFLOW_REVIEW.md` and `../../docs/REEL_PLAN_FORMAT.md`. Use native choice/input forms for questions. Resolve the studio two directories above this skill. Run its local effects Python with `scripts/reel_workflow.py COMMAND`. No external model API is needed for speech, trimming or rendering.

1. Run `doctor` and `list`. For a bare invocation, offer up to three recent recording folders with native choices; preserve all takes in the chosen folder. A supplied folder can be used directly. An existing slug resumes `status` and saved feedback. For a script-first draft, use `../wf-reel-plan/SKILL.md`, then `attach` without overwriting the approved script.
2. Run `init --project SLUG --folder ABSOLUTE_INPUTS_FOLDER --title TITLE`; optional `--script-html` imports expected spoken lines. New projects use `pipeline_version: 2`, Vibha then Hyperframes. Existing plans retain their recorded renderer; never migrate an authored Remotion or manual Hyperframes composition automatically.
3. Run `quality --project SLUG`. Matching profiles select portrait output automatically: 4K/60 → 2160×3840 at 60, 4K/30 → same at 30, 1080p/60 → 1080×1920 at 60. Fractional rates remain exact. Mixed resolutions/rates, variable-rate or unsupported sources require an explicit native choice and `profile --project SLUG --width W --height H --fps RATE`. Explain crop/scaling: landscape-to-portrait can discard pixels and upscale. Review the crop in actual frames. Never silently choose the lowest/highest source or 30 FPS.
4. Run `analyze --project SLUG`. One local model is loaded per batch; cached transcripts and trims are reused. Read detailed analysis files only for affected scenes. Compare actual speech with the expected script and source audio. Correct `say`, relative timed `words`, and `caption_pages` together; mark `text_confirmed` only after checking. Uncertain segments may get a targeted second pass (`scripts/speech_segment.py`), never automatic replacement by the expected script. Set the known `language` before analysis.
5. Discuss visual choices with sample images from `../effects/references/catalogue.json`. Keep suggestions pending. In each shot, set `vibha.status` to `selected` with approved numbered effects, or explicit `none`; record the exact selection in top-level `visual_selection`. Keep `remotion.status: none` in new Hyperframes reels. `focus: [x,y]` controls crop. Vibha effect `start`/`end` are relative to the trimmed shot; preserve approved label text in effect options. Vibha never adds spoken subtitles. Keep new layouts `full`; author additional composition graphics in Hyperframes.
6. Run `plan --project SLUG`, then prepare a `plan` review as documented. Full script first, integrated scene table second. Fields support independent script and scene feedback; approval confirms the plan/visual choices, not unseen frames.
7. Suggest suitable music and sound cues from `assets/audio/catalogue.json` (4 music tracks,23 SFX, original CC0 notices). Set `audio.recommended_music` and initially `audio.music` to the recommended stable ID, `music_gain` up to 0.3, and `sfx: [{scene, sound, at, gain}]` with valid local timings. Do not choose music by its filename alone; audition where useful. The final page lets the user play alternatives and choose no music. A sample of up to 8s mixes selected music/cues with the authoritative source voice. Playing alone is not approval.
8. Run `preview --project SLUG`. The helper renders actual Vibha stills, then captures them with the authored Hyperframes captions at matching times. No full effected clips are rendered yet. It reuses cached normalization/audio/stills and builds a native-resolution editable composition. For custom finishing, read `tools/hyperframes/node_modules/hyperframes/dist/skills/hyperframes/SKILL.md` and CLI references, use the local wrapper and preserve managed source paths/audio markers. `Launch Hyperframes Studio` handles direct visual edits. Never reintroduce a custom review canvas.
9. Inspect every actual frame for crops, face overlap, readable captions/labels, entrances/exits and correctness. Prepare a `frames` review, show its URL and collect feedback independently per frame. Selecting music makes a fresh audio sample/revision and retains valid visual frames; caption/visual edits require fresh previews. Resolve pending feedback and acknowledge it before final approval.
10. After explicit approval of the current frames and audio, run `approve --project SLUG --preview-id CURRENT_ID --message "Exact user approval"`, then `render --project SLUG`. Never manufacture approval. The helper checks source/engine/profile/composition/frame/audio fingerprints, renders full caption-free Vibha clips, reuses them for audio/caption revisions, and finishes with Hyperframes. All shot videos are muted; one authoritative source-voice track carries speech, with one spoken-caption composition plus optional music/SFX. Encoded dimensions, exact FPS, frame count, duration, audio and decode checks must pass. Inspect the final video/audio synchronization as well.
11. Write accurate posting copy to `export/caption.txt`; use an actual cover from `export/cover.png` or an approved authored cover. The dashboard discovers the media, cover and copy. Do not generate speech or publish socially. Give the video path and ask the user to watch before posting.

For legacy Remotion projects, preserve bundled scenes, prior decisions and existing preview/approve/render helpers. Manually authored legacy Hyperframes projects keep their explicit export process. No automatic rewriting of existing exports.

Setup: Node 22.18+, local ffmpeg/ffprobe and the effects environment (`../effects/SKILL.md`). Install Hyperframes with `npm ci` in `tools/hyperframes/` when missing; use `node tools/hyperframes/hyperframes.mjs COMMAND ABSOLUTE_COMPOSITION_DIR`. New workflow supports even portrait9:16 profiles up to2160×3840 and 60 FPS. Unsupported profiles require an explicit supported choice. Smaller review pictures never become production video sources.
