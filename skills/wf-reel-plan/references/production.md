# Shared recorded production

This is an internal reference for both planning commands. Resolve all paths from the studio root. Use the local effects Python to run `scripts/reel_workflow.py`. Every command accepts `--kind reels` or `--kind videos`; include it on EVERY invocation, including status, analysis, audio, approval and render. Omission defaults to reels for existing callers.

For any India/state map or regional/world map including India, follow `skills/india-map/SKILL.md` before authoring its graphics. Use the verified official-boundary asset in the selected renderer and show it in actual-frame review.

The planning entry point has already initialised or attached the recordings. Continue at quality inspection. For a saved legacy project, preserve its renderer and authored media. Keep all questions and review submissions in the active planning workflow.

3. Run `quality --kind KIND --project SLUG`. Matching profiles select the intended orientation automatically. Reels use portrait output: 4K/60 → 2160×3840 at 60, 4K/30 → same at 30, 1080p/60 → 1080×1920 at 60. Fractional rates remain exact. Mixed resolutions/rates, variable-rate or unsupported sources require an explicit native choice and `profile --kind KIND --project SLUG --width W --height H --fps RATE`. Explain crop/scaling: landscape-to-portrait can discard pixels and upscale. Review the crop in actual frames. Never silently choose the lowest/highest source or 30 FPS.
4. Run `analyze --kind KIND --project SLUG`. One local model is loaded per batch; cached transcripts and trims are reused. Read detailed analysis files only for affected scenes. Compare actual speech with the expected script and source audio. Correct `say`, relative timed `words`, and `caption_pages` together; mark `text_confirmed` only after checking. Uncertain segments may get a targeted second pass (`scripts/speech_segment.py`), never automatic replacement by the expected script. Set the known `language` before analysis.
For speech-free scenes or a fully narrated project, follow `skills/natural-narration/SKILL.md`. Audition the actual approved words in each scene and use the selected take’s timings.
Before populating visual choices, follow `skills/wf-reel-plan/references/reference-style.md`. Ask only after actual footage is ready, and only when the library has videos and the project has no saved choice. Reuse a selected style snapshot or a saved No reference choice on resume. Apply reference patterns through proposed scene treatments and keep actual-frame approval.

5. **Populate visual effect suggestions; never ask effect choices in chat.**
Do NOT prompt the creator about visual effects in chat. Visual choices must be reviewed visually with dummy sample cards in the interactive HTML plan. In each shot, set `vibha.status: "pending"`, provide a clear `none_suggestion` (such as natural studio framing with clean blurred backdrop and no overlay graphics), and add 2 to 3 tailored effect `suggestions` from `skills/effects/references/catalogue.json`. Each suggestion MUST include an integer `id` that maps to the catalogue, plus `title`, `reason`, and any relevant options tailored to the scene dialogue using `skills/effect-tailor/SKILL.md`. Never use generic placeholder template text in effect options. Keep `remotion.status: "none"` in new Hyperframes reels. `focus: [x,y]` controls crop. Vibha effect `start`/`end` are relative to the trimmed shot; preserve approved label text in effect options. Vibha never adds spoken subtitles. Keep new layouts `full`; author additional composition graphics in Hyperframes.

For requested natural studio lighting, read `docs/STUDIO_LIGHTING.md`. Set project-level `lighting: {"preset":"natural-studio"}` or a per-shot setting; `lighting: null` disables it for that shot. The compiled `studio-light` runs before existing graphics, including on clean Vibha shots. Keep the script, cuts, captions, audio and authored Hyperframes layers. Calibrate visible displays on actual footage, retain exact output quality, inspect every shot and preserve frame/audio approval. Existing intentionally stylized grades may alter the lighting afterwards; do not remove them silently. Nafay remains separate.

6. **Generate plan and present interactive HTML review.**
Run `plan --kind KIND --project SLUG`, then prepare the `plan` review: `node scripts/review.mjs prepare --kind KIND --id SLUG --stage plan --document outputs/KIND/SLUG/review.html`. Immediately open and present the interactive review URL (`http://127.0.0.1:4173/review/KIND/SLUG`) to the creator. The creator inspects the full script and scene table, views dummy reference cards for suggested effects, and selects their choice directly from the effect dropdown in the review UI. Wait for or read the user submission (`node scripts/review.mjs wait --kind KIND --id SLUG`). Once submitted, record the chosen effect in `vibha.status: "selected"` (or `"none"`) and top-level `visual_selection`. Approval confirms the plan and visual choices, not unseen frames.
7. Follow `skills/sound-design/SKILL.md` for music and scene cues. Review the full voice/music/effects mix and listen to every narrated scene.
8. Run `preview --kind KIND --project SLUG`. The helper renders actual Vibha stills, then captures them with the authored Hyperframes captions at matching times. No full effected clips are rendered yet. It reuses cached normalization/audio/stills and builds a native-resolution editable composition. For custom finishing, read `tools/hyperframes/node_modules/hyperframes/dist/skills/hyperframes/SKILL.md` and CLI references, use the local wrapper and preserve managed source paths/audio markers. `Launch Hyperframes Studio` handles direct visual edits. Never reintroduce a custom review canvas.
9. Inspect every actual frame for crops, face overlap, readable captions/labels, entrances/exits and correctness. Prepare a `frames` review, show its URL and collect feedback independently per frame. Selecting music makes a fresh full mix and revision and retains valid visual frames; caption/visual edits require fresh previews. Resolve pending feedback and acknowledge it before final approval.
10. After explicit approval of the current frames and audio, run `approve --kind KIND --project SLUG --preview-id CURRENT_ID --message "Exact user approval"`, then `render --kind KIND --project SLUG`. Never manufacture approval. The helper checks source/engine/profile/composition/frame/audio fingerprints, renders full caption-free Vibha clips, reuses them for audio/caption revisions, and finishes with Hyperframes. All shot videos are muted; the reviewed mix carries the recorded dialogue, chosen narration, music and sound cues. Encoded dimensions, exact FPS, frame count, duration, audio and decode checks must pass. Inspect the final video/audio synchronization as well.
11. After rendering, follow `skills/cover-image/SKILL.md` to create `export/cover.png` in the shared channel style, unless a different cover or no cover was requested. Follow `docs/SOCIAL_COPY.md` for posting copy: default to Instagram, YouTube title/description, TikTok and LinkedIn, with natural writing and no em dashes. Update the existing posting-copy file, or create `publishing/Social_Copy.md`. The dashboard discovers the media, cover and copy. Publishing stays a separate decision. Give the video path and ask the user to watch before posting.

For legacy Remotion projects, preserve bundled scenes, prior decisions and existing preview/approve/render helpers. Manually authored legacy Hyperframes projects keep their explicit export process. No automatic rewriting of existing exports.

For YouTube videos, matching landscape 4K/60 sources produce 3840×2160 at 60 FPS. Use short-side sizing for Vibha and landscape caption safe areas. Adapt each selected effect for landscape and inspect its actual stills for overlap/clipping. Where it cannot be fitted, discuss an alternative before rendering. Never silently change the selected effect.

Setup: Node 22.18+, local ffmpeg/ffprobe and the effects environment (`skills/effects/SKILL.md`). Install Hyperframes with `npm ci` in `tools/hyperframes/` when missing; use `node tools/hyperframes/hyperframes.mjs COMMAND ABSOLUTE_COMPOSITION_DIR`. New projects support even portrait 9:16 up to 2160×3840 and landscape 16:9 up to 3840×2160, at 1–60 FPS. Unsupported profiles require an explicit supported choice. Smaller review pictures never become production video sources.
