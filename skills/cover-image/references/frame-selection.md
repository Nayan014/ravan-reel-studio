## Optional video-frame selection

Use this procedure only when the user explicitly asks to take their portrait from the video. Show several actual frames and wait for their selection. Follow `../../docs/WORKFLOW_REVIEW.md` for native choice/input forms. Acceptance of a cover style does not select a portrait.

- Extract a small set, usually 4–6 distinct sharp frames, with varied expressions and eyes open where available. Respect display rotation. Use fewer if a short clip has few useful frames; do not pad the choices with duplicates or generate candidate faces.
- Present the actual frame images in a user-facing message, numbered and labelled with their source timestamps, at a size where the face is easy to compare. A tool-only image inspection is for the agent and does not count as showing the user the frames.
- In Codex, embed a numbered contact sheet directly in the reply using standard Markdown image syntax with an absolute local path, for example `![Portrait choices: frames 1–6 with timestamps](/absolute/project/path/portrait-choices.jpg)`. Use the real saved path, not this example. Do not use relative paths, file:// URLs, plain file links or timestamp-only options as the visual presentation. If the sheet makes faces too small, embed individual face-and-shoulder preview images with their matching numbers and times. Keep the full source frames intact.
- Show the image previews before sending the native choice form. Offer the matching frame numbers, plus More frames and Use my own photo. When yielding for the choice, include the preview image embed again in the final response so it remains visible after commentary/tool output is collapsed. Do not assume that a successful image-inspection tool call means the user can see it.
- If the user reports missing or unreadable images, keep portrait selection pending and repair the presentation first: check that preview files exist and decode, embed the actual images again, and use the host's file/image preview panel or a local image gallery if inline display still fails. Do not ask them to select from timestamps alone or choose a face on their behalf. Do not claim user-visible rendering has been verified solely because the files decode.
- Wait for an explicit choice before composing or generating a cover that uses their likeness. Topic analysis and headline preparation can continue while waiting. A recommendation, default selection, silence or previous cover-style approval is not a frame selection.
- Save the selected frame path, source-video fingerprint, timestamp and exact selection message in the project's `publishing/cover/brief.json`. Use that frame as the portrait reference, preserving its expression and recognizable likeness. Do not silently substitute another frame or invent a different expression.
- On revision/resume, reuse an explicit saved selection for the unchanged source unless the user wants another frame. A changed source or a request for another face returns to frame selection. If the user explicitly supplies a photo or specifies an exact frame for this cover, use that choice without repeating the picker. A cover without the creator's likeness does not need this step.
